# 主站按页面加载优化（已部署）

已检查主站 20 个页面面板，包括现货、合约、美股复用的交易终端，以及矿机、资产、跟单、积分、推荐、客服、策略总览与三个策略页。后台管理页面不在本次范围。

## 改动

- 页面脚本改为按实际依赖加载，共享脚本只下载一次。一个页面的慢脚本不会挡住其他页面；失败后可重试。
- 交易终端先显示价格、盘口与账户，图表库下载完成后补画蜡烛；AIX 同样先显示价格和余额。策略总览不下载图表，策略页面按需下载图表。
- 资产的钱包数量与平台估值并行更新；打开充值/提现时才读取资金配置，点击 AIX 互转/提现时才下载弹窗脚本。互转记录和收益记录仍在打开对应标签后读取。
- 质押的平台数据与外部验证者独立渲染，外部接口失败保留平台数据和输入内容。补齐直接进入质押页缺失的 Hyperliquid 客户端依赖。
- 投资组合的持仓、现货、委托和金库分别返回、分别显示；尚未返回的总值保留占位，不把失败伪装为零余额。
- 积分页立即显示结构，积分、奖品配置和所选记录分别读取。积分和配置就绪后才开放抽奖，失败提供刷新入口。
- 离开 AIX、客服、抽奖、跟单、AI 或策略页后停止其网络轮询/行情连接。返回页面后恢复所需刷新；策略的服务端运行不受前端连接关闭影响。
- 普通资料刷新不再重置所有隐藏页面。同一钱包的并发只读请求合并，完成响应不作余额缓存；交易和资金操作保持原来的请求流程。
- 页面刷新、切换钱包、切换交易对/周期、切换账本筛选和抽奖标签均防止过期响应覆盖最新数据。
- 修复金库页面金额使用零位小数时出现的 `maximumFractionDigits value is out of range`。
- 社群和白皮书保持其已有按需加载/静态内容方式。排行榜、账本、推荐、金库增加或保留请求超时及独立错误处理。

仅修改前端及测试入口，未修改后台资产、奖励计算或生产数据库。生产发布已完成，详情见下方部署记录。
