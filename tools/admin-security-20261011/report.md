# 图片审核、客服显示与独立资金后台

本次安全修复与独立资金后台已部署，并通过线上接口、公网响应与浏览器验证。发布脚本没有执行生产加款、扣款、提现审核或奖励补发，提现设置与冻结状态保持不变。正常服务启动后会继续同步用户和团队状态。

## 线上检查

最新只读快照检查了 106 条社交审核记录与 22 条客服消息。截图校验包括声明类型、规范 Base64 和 PNG/JPEG/GIF/WEBP 文件头。攻击特征检查对 HTML 实体、URL 编码和 data URL 内的 Base64 内容解码后匹配。

50 条历史截图不符合当前图片标准：空内容 1 条、历史 HTTP 链接 31 条、文本 13 条、其他 data URL 5 条，均处于已通过状态。其中 2 条含脚本，其他无效截图不能据此认定恶意。最初的明文扫描漏掉这两条编码内容，解码扫描已纠正。客服消息中未发现匹配的脚本特征。

| ss_f0178e4ea0f6a05e8e26 | 0x5f5329384f6091200fd39fe2578882fe3eb676e1 | SVG data URL，onload 调用 alert | 2026-10-10 04:07:29 |

两条记录均通过 admin 审核，分别授予 10 积分。它们没有访问 cookie、存储或资金接口的代码；对应账户的 USDT、AIX、BTC、ETH、BNB 账面余额均为零，余额调整记录均为零。这些事实不能单独证明提交者身份或历史资金行为。现在线上的图片预览已经限定栅格图片，能够阻止这两种 data URL 打开。

证据：`production-scan.json`、`script-records.json`。存量记录保留用于审计，本次没有将脚本探测账户认定为盗币账户并删除。

## 修复与整合

- 截图审核列表在服务端重新校验历史记录；无效图片不再返回原始截图内容，并显示“截图无效”。通过待审核记录前再次校验，失败时不变更状态、不发积分；已通过记录同样经过安全过滤。
- 截图预览改为页面内弹窗，使用没有脚本及同源权限的 sandbox iframe，不打开继承后台权限的新窗口。
- 运营后台与用户端客服正文均用 `textContent` 和 DOM 节点显示，保留换行；HTML、事件属性和脚本内容按文字显示。列表预览原有转义保留。
- 运营后台采用不允许内联脚本/事件属性的 CSP。移除后台对整套交易 core.js 的依赖，使用独立的纯文本对话框；股票图标兜底改为事件监听，兼容严格 CSP。资金后台采用更严格的 CSP。编码入口路径、Windows 路径大小写与静态缓存也纳入处理。
- 新入口 `public/funds-admin.html` 将 USDT 测试入账、记录查询、提现审核、手动交易哈希核验、自动出款放行/重试、退款以及原提现设置整合在一起。沿用已有 `WALLET_ADMIN_TOKEN`，不新增默认凭据。
- 所有资金 API 统一走 `/api/wallet/admin/*` 的独立令牌验证，运营 cookie 没有资金权限；原 `/api/admin/test-credits`、`/api/admin/withdrawals`、`/api/admin/withdrawal-automation` 路径拒绝访问，旧资金写入处理代码移除。
- 运营后台只保留打开资金后台的入口，不加载入账或提现面板和 API。旧提现入口跳转到新资金后台。
- 令牌只保留在当前页面内存；清除旧页面保存的 `wd_admin_token`，锁定时清除令牌及表格，过期请求不能回写画面。测试入账失败重试保留请求编号，使用原账本幂等和审计流程。
- Service Worker v9 排除资金后台和编码后的后台入口。客服、加载器和首页引用升级版本，防止旧脚本继续命中缓存。

资金后台使用独立页面和令牌权限，仍在同一站点和应用服务内；本次没有创建独立域名或新服务器。原资金账本、链上支付核验、提现冻结和出款服务实现保持原样。
