## 对当前版本的判断

当前版本已有回合、历史、核验和设置，结构基本齐全。简陋感主要出在交互组织与节奏：

1. 手机首屏中，大标题、装饰星盘和步骤条占用较多高度，完整的参与额与确认按钮需要滚动。
2. 星盘插画承担主视觉，但真正决定玩法的 0–F 数字条很小。玩家难以把自己的选择与命中数字直接对应起来。
3. 本地单人每局仍执行 15 秒选择加 3 秒锁定。它采用定时回合节奏，却没有多人共享回合的实际需求。
4. 揭晓、自己的预测、积分变化与下一步动作分散，缺少紧凑的单局结果总结。
5. 确认后、等待时和结算后的界面需要更明确的视觉层次，减少重复说明。

## 推荐的下一版

### 优先一：手机单屏完成一次操作

保留 AIX 紫色/薄荷绿识别，游戏页压缩标题与装饰。390×844 的手机上，应在首屏看到当前回合、结果区、单双/大小、参与额、预计返还与主按钮；320 像素宽度允许合理滚动，但主按钮应持续可达，输入法与底部导航不遮挡操作。

游戏页建议顺序：

```text
顶部：AIX HASH / 试玩星点 / 帮助与声音
最近回合：横向数字结果
主区域：当前回合与状态 → 0–F 数字星盘 → 本局结果
操作区：单 双 小 大 → 参与额 → 命中返还 → 主按钮
辅助：本局详情与核验
```

大厅可保留完整插画，实际游戏中缩小装饰占比。历史、核验、规则页面继续保留，作为辅助入口。

### 优先二：把数字变成主要互动对象

把现有的小数字条提升为清楚可读的 2×8 或环形数字区域。选择「单」时强调八个奇数，选择「大」时强调 8–F；揭晓后准确突出实际末位，并并列展示十进制值与单双/大小归属。

动画使用同一套数字盘、轨道与颜色系统，结果提示同时有文字和符号，不能只靠颜色区分。插画继续作为氛围背景，减弱遮挡。

### 优先三：明确单人节奏

建议默认采用**手动快速回合**：选择和确认后，用约 1–2 秒完成揭晓表现。每局依然由玩家主动确认，保持一次参与与一次结算。

如要保留 15+3 秒，作为有明确名称的「定时回合」体验另行设计，不把它与单人快速体验混在一起。快速模式涉及状态与存档规则变化，应作为独立实现任务设计恢复及结算兼容，不能只把 UI 倒计时改短。

这里借鉴 Dice 的操作节奏；Aviator 用于参考状态与反馈，暂不引入其倍率退出规则。

### 优先四：结果卡与详情弹层

揭晓后，原操作区域用紧凑结果卡展示：实际末位、自己的预测、参与额、返还、净变化，以及明确的下一回合动作。点击记录打开单局详情；技术字段与完整核验可进一步展开。

已有历史列表应继续显示实际回合；统计需要标清范围。没有参与的回合应直接写「未参与」。

### 优先五：统一视听与交互状态

统一按钮、图标、圆角、数字字体和字级。选择、确认、锁定与揭晓各有短促、节制的反馈。减少动态效果设置应覆盖揭晓过程，减少动态时仍能立即读懂结果。

错误显示在当前操作附近；处理中、已经确认和当前不可操作时，按钮需说明状态。鼠标、触摸和键盘都可完成主要流程。

## 后续顺序

先完成单屏布局、数字盘、手动快速回合、结果卡，再考虑其他玩法与大厅扩展。任务、徽章和收藏的优先级后移；它们对当前核心体验的改善较小。

适合当前项目的方向是：**SPRIBE Dice 的集中操作 + Aviator 的清晰回合反馈 + 可展开的记录与核验 + AIX 自有美术。**
