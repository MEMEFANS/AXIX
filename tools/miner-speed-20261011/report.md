# 矿机页面与团队人数加载优化

日期：2026-10-11（北京时间）。状态：已于 05:29:41 发布生产并重启线上服务，源站与公网验证通过。本地 Node 服务仍未重启。

原因：矿机首页只取得基础账户快照，其中不含团队人数；完整团队接口包含收益、持仓及下级明细，在每个直推用户的计算中重复读取并重建整张推荐关系表。前端等待个人资料、团队资料及邀请码全部返回后才显示结果。

修改：

- 新增需要钱包登录的 `/api/a-token/team/summary`，只读取推荐关系及已有展示叠加值，计算直推人数、团队总人数和上级；不读取余额、收益或矿机持仓，也不写等级快照。
- 矿机首页请求轻量人数接口，个人矿机、人数、团队明细和邀请链接各自返回即显示。完整团队明细在进入团队标签时请求。
- 同一钱包相同读请求在进行期间复用，避免重复点击发起重复查询。缓存按钱包隔离，切换及退出后废弃旧请求。
- 完整团队查询在一次请求内复用推荐树、下级持仓和展示叠加上下文，把 100 个直推测试账户对应的全表推荐关系读取从 105 次降为 4 次。
- 未加载的人数显示占位，接口真实零人数显示零。基础账户刷新保留独立加载的团队数据。
- 旧后端缺少轻量接口时，404/405 回退完整团队接口，保持服务升级前的页面兼容。脚本版本更新为 `20261011-team-fast-2`。

验证：`test:earn-team-loading`、`test:asset-reporting`、手机钱包启动、钱包状态竞态及手机登录恢复专项测试通过。502 钱包测试中轻量人数查询 2.32 毫秒，完整团队查询由 181.47 毫秒降到 37.78 毫秒；该数字为本机测试数据，不是生产或用户弱网速度承诺。手机视口模拟接口中人数先于未返回的矿机资料显示，团队收益先于未返回的邀请码显示；切换钱包与旧接口回退验证通过。

优化前后完整团队 profile 逐字段一致，包括 601 条历史奖励累计、余额、质押本金、等级、展示叠加与矿机人数。测试未修改真实余额或发奖。另在隔离的本地 SQLite 副本上验证已有账户的完整 profile 一致。
