# 手机自动签名与首屏响应修复

线上地址：https://axix.cc/ 。本次发布结果详见 `deployment-result.json`，公网验证详见 `live-verification.json`。

截图显示钱包地址已连接、身份验证未完成，并出现网络请求超时。代码排查确认以下阻塞路径：签名消息请求超时会结束自动登录；签名提交后需要完整钱包资料，而钱包资料接口会先等待待到账充值的链上 RPC 核对；矿机首屏原先等待方案接口两轮重试，最长约 16 秒才显示卡片。

## 已完成

- 登录使用轻量 cookie 会话接口 `/api/wallet/session`，无需等待资金资料或 RPC；完整资金查询在资产页进行。
- 登录消息与 BSC 网络检查并行；临时网络失败最多重试一次。相同请求编号获得相同挑战，避免重试乱序使签名失效，签名仍然只能使用一次。
- 钱包签名请求不会自动重复。自动流程被钱包限制或用户取消后，顶部地址和页面“确认钱包”按钮提供手动重试。
- 矿机先显示缓存/浏览配置，后台刷新当前方案；付款前必须取得最新方案及激活记录。
- 团队与推荐接口在团队标签打开时加载，矿机标签定时刷新也只获取矿机资料。
- 首屏脚本从 9 个减少到 8 个；资金操作脚本在资产页打开时下载。钱包连接器预加载，翻译词典按语言异步加载。
- 简体中文时钟和金额更新不再引起整页翻译扫描；其他 7 种语言切换与还原回归通过。
- 缓存已有版本的静态文件不再重复下载与登录请求竞争；API 和签名提交继续绕过静态缓存。
- 保留本地原始版本已包含的最新 `server.js` 更新；生产文件切换前再次核验 SHA256，完整备份 8 个发布文件，并验证后端重启成功。

## 验证

以下相关测试均通过：`mobile-auth-recovery.test.js`、`mobile-wallet-startup.test.js`、`earn-wallet-state.test.js`、`wallet-session.test.js`、`wallet-connector.test.js`、`i18n.test.js`、`mobile-static-cache.test.js`，以及发布 JavaScript 语法检查。

浏览器模拟覆盖首次消息请求失败后的单次签名、弱网下卡片先显示、取消签名后仅在主动点击时重试、旧请求 401、断开/切换账户竞态、团队按需加载、简体中文时钟性能、7 种语言、付款配置不可用时阻止交易。模拟启动约 0.7–1.1 秒；这不是用户手机实际测速，也不保证钱包厂商允许自动弹窗。

公网 6 个发布前端文件均返回 HTTP 200，内容与本地逐字节一致；轻量会话接口返回 HTTP 200、未登录状态和 `Cache-Control: no-store`；两次同编号登录挑战返回同一消息。未操作用户钱包或执行真实付款。

本地 8082 服务的重启、独立预览实例启动均被自动审批拦截，工具只返回 `blocked by policy`，没有提供具体原因。本地原进程仍保留；本次使用浏览器模拟回归和生产接口完成验证。
