# 本地修复记录

本次按自动转账提现流程修复，已于 2026-10-14 部署生产；部署验证未广播真实交易，未修改配置或合约。自动转账不等于 AIXPool 用户领取；前一份报告中的签名问题属于另一个未配置合约地址的路径。

自动 AIX 转账提现：
- RPC 错误和广播超时不再根据“失败/revert”字样退款，继续保留原交易及余额冻结。
- 链上失败交易必须达到 12 个确认才退款；退款与订单状态原子提交，重复扫描不重复退款。
- 待审核撤销/拒绝仍支持正常退款，同样使用原子事务。
- 提交扣款与提现记录同事务保存，故障时同时恢复内存和数据库余额。
- 请求编号查找不再只扫描最近 50 条；金额不同的重试明确拒绝。
- 串行出款减少同一热钱包并发分配 nonce 的风险。
- 使用精确 18 位金额及 BigInt 日额度汇总，修正日额度查询毫秒/秒不一致，并排除已取消记录。

未启用的 AIXPool 领取路径也完成 EIP-191、原子扣账和链上确认校验修复；旧合约无法撤销授权，因此此路径禁止超时退款。没有部署或要求部署新合约。这不影响自动转账提现的安全失败退款。

依赖：更新 undici 和 http-cache-semantics；覆盖 tmp 为修复版本。solc 保留原来的 0.8.20 并固定版本，避免改变编译器；没有重新生成合约产物。应用完整 npm audit 为零漏洞。

验证通过：新增 claim/自动提现安全测试；管理员安全、资金权限、钱包会话、行情、自动出款、闪兑、跨链出款测试。新测试覆盖数据库写入失败回滚、广播错误不退款、链上失败确认前不退款及确认后只退一次、历史幂等和精确日额度。
