# 本地安全审查（2026-10-14）

范围：resources/app 当前业务代码、AIXPool 合约源码和生产依赖锁文件。进行了本地隔离复现与部分现有测试；没有连接生产服务器、发送链上交易、修改业务代码或读取输出任何密钥值。本报告不是完整渗透测试，也不证明线上部署与本地相同。

## 1. 高风险设计缺陷：提取自动退款不核查链上、不撤销授权

位置：src/a-token-claim-service.js:224–253；src/server.js:616–624；contracts/AIXPool.sol:106–129。

sweepStaleClaims 只凭数据库 pending 和本地 expiresAt 自动退回余额。confirmClaim 由前端主动请求，不能保证已领取的记录一定被确认。退款前既没有查询链上领取事件或 isClaimUsed，也没有撤销原来的 nonce。合约签名消息没有 deadline，harvest 也没有到期验证或单笔授权撤销机制。

如果签名能够通过合约验证，用户可以领取后不调用 claim-confirm，等自动退款；或者等退款后再用尚未消费的签名领取。账面退款与链上出款可同时发生，造成资产重复支出。

**当前利用条件必须说明：** 第 2 项签名错误会阻止本地当前实现生成的授权通过所附合约验证。因此本项不是已证明当前线上可盗币的漏洞，而是修复签名前必须一起修复的高风险资金设计。仅修签名会使风险显现。是否线上存在不同合约或历史有效授权没有核查。

建议：在签名和合约中绑定 chainId、deadline 和唯一授权编号；过期后等到安全确认区块并核查领取状态，再原子退款。未过期授权应先完成链上撤销并确认；不能只依赖前端确认。

## 2. 签名协议错误：扣款后发出的签名无法通过合约

位置：src/a-token-claim-service.js:157–186，尤其第 168 行；contracts/AIXPool.sol:118–120。

服务使用 signingKey.sign(msgHash) 直接签原始哈希；合约却先执行 toEthSignedMessageHash，再恢复签名地址。隔离测试证明原始哈希恢复出平台签名地址，而按合约 EIP-191 恢复出的地址不同。启用这套服务和合约后，用户被扣账面余额，但链上领取失败。

建议：统一 EIP-191 或 EIP-712 协议，添加真实合约验证测试，并与第 1 项同步修复。

## 3. 中风险：余额变动和提取记录更新没有原子性

位置：src/a-token-claim-service.js:157、186、229–235；src/a-token-service.js:284、301。

signClaim 先 debitA，再单独写 claim；记录写入失败时没有回滚，形成扣款但无记录、自动退款也找不到的状态。refundClaim 先 creditA 再写 refunded；后一步失败会留下 pending，下一次扫描可能再退一次。

本地注入一次记录写入错误，确认余额从 1000 AIX 降至 900 AIX，同时 claim 记录为零。退款重复入账路径为代码审查结论，未对真实数据库制造故障。

建议：余额、claim 状态及审计记录放进同一数据库事务，配合条件状态更新防止重复退款；同时考虑 wallet-service 内存状态在事务失败时的一致性。

## 4. 依赖扫描：两个高危依赖项

在 resources/app 运行 npm audit --omit=dev --json，报告 2 个 high 依赖项（不等于两个已可从公网利用的入口）：

- undici 6.28.0：WebSocket 异常子协议/解压导致拒绝服务等公告，修复版本为 6.28.1 或更高兼容修复版本。src/market-data/public.js:4 确实导入其 WebSocket；当前连接目标主要是行情上游，普通网站用户是否可控制恶意上游响应未证明。公告：https://github.com/advisories/GHSA-rfgv-xxqx-mfg5
- http-cache-semantics 4.2.0：缓存跨用户响应泄漏公告，经 @aptos-labs/ts-sdk → @aptos-labs/aptos-client → got → cacheable-request 引入。尚未证明本应用启用了受影响缓存场景。应升级到公告修复版本，并验证 SDK 兼容性。公告：https://github.com/advisories/GHSA-ch52-4w7c-c8xp

- node tools/security-audit-20261014/reproduce.mjs：通过。使用随机临时密钥、内存余额和假数据库，不访问 RPC。
- node test/wallet-session.test.js：通过。
- node test/admin-security.test.js：未完整通过。前两组策略及截图校验通过，但第 58 行测试希望客服接受攻击文本，当前 support-service 会拒绝该文本，测试因此中断。这说明测试与当前防护行为不一致，不能宣称整套后台安全测试通过。
