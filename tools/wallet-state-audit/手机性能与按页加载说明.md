# 手机端初始化和按页加载优化

日期：2026-10-10

## 钱包初始化问题

手机钱包已经注入 provider，但 `eth_accounts` 首次返回空账户时，等待函数提前读取尚未初始化的计时器，抛出异常，导致截图中的“钱包连接器初始化失败”。已修正变量初始化和计时器、事件监听清理。

钱包脚本现在直接加载，不再排在交易图表等多个脚本之后。连接和签名不等待充值提现配置接口；配置在打开个人资产页时读取。已给钱包 HTTP 请求、账户读取和钱包确认设置时间限制，防止长时间挂起；短暂网络失败不会误清除已认证状态。钱包已经在目标 BSC 网络时跳过多余的切链请求。

## 按页面加载

- 进站矿机页：只加载主题、翻译引擎、基础导航、页面加载器、矿机与钱包脚本。
- 现货、合约和股票：第一次进入才下载交易图表和交易终端模块。
- 个人资产：只加载账户、资产和资金功能，无需交易图表。
- 跟单、策略、抽奖、交易大厅、推荐、排行榜、社群和客服：打开对应页面后才加载模块。
- 共享脚本只加载一次；已访问页面复用脚本。加载期间显示“加载中”，快速切页不会在请求完成后切回旧页面。
- 离开交易页时关闭行情推送；隐藏页面停止交易轮询。跟单分析也只在跟单页运行。

中文启动时自动请求的 JavaScript 从 31 个减少为 9 个。按当前脚本源码统计，未压缩体积从 753,191 字节减少到 207,178 字节。这是脚本资源量比较，不代表真实手机的耗时比例。详情见 `lazy-loading-measurement.json`。

## 验证

- 手机尺寸的真实页面结构，模拟钱包首次返回空账户：连接、签名和认证按钮正常，没有初始化异常。
- 矿机首屏不请求图表、资金配置、抽奖、跟单、策略或个人资产脚本；测试实际观察到 9 个启动脚本。
- 第一次进入资产无需图表；第一次进入交易才请求图表；共享脚本与图表不重复下载。
- 下载图表途中切回矿机页，不会被迟到请求切回交易页。
- 交易页行情请求正常，矿机页不发起隐藏交易行情轮询。
- 其他主站模块首次下载执行，无缺失依赖导致的页面异常。
- 钱包状态、断开与切换账户、签名取消、旧响应、真实会话过期和 7 种语言回归测试通过。
- 隔离浏览器使用模拟钱包，所有交易接口均拦截，没有真实签名、资金操作或链上交易。

主要回归入口：`resources/app/test/mobile-wallet-startup.test.js`、`earn-wallet-state.test.js`、`wallet-connector.test.js`、`wallet-session.test.js` 和 `i18n.test.js`。
